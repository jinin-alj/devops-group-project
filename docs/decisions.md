## 1. Deployment and pipeline

**Date:** 2026-11-24  
**Owner:** Salome Shioshvili

**Context**  
The brief requires a one-time Azure setup that is scripted or written as IaC, then every merge to `main` must deploy itself. Nothing should be changed by hand in Azure after that. The group already has a resource group (`rg-sdd-3b-g7`) and will get a group service principal for the pipeline.

**Decision**  
- One-time setup is an Azure CLI script (`infra/setup.sh`), run with `CLASS=3b GROUP=7`.
- CD is a GitHub Actions workflow (`.github/workflows/cd.yml`) that runs CI, pushes both images to GHCR tagged with the commit SHA, updates both Container Apps, checks `/health`, then deploys the UI to Static Web Apps with Azure URLs written into `ui/config.js`.
- The pipeline logs in with the group service principal stored as the GitHub secret `AZURE_CREDENTIALS`.
- Database passwords are generated by the setup script and stored only as Container Apps secrets, never in the repository.

**Alternatives**  
- Bicep or Terraform for the setup (credited, but the CLI script is enough and matches what we already know from Assignment 2).
- Deploying from a personal resource group or the Assignment 2 service principal (rejected: the brief requires the group resource group and the group service principal).

**Consequences**  
- Anyone with access can reproduce the Azure setup from a clean machine.
- The first image push may need the GHCR packages set to public so Azure can pull them without a registry password.
- Until Contributor access and the service principal are granted, the script and the workflow can be reviewed in the repository but cannot be run end to end.
